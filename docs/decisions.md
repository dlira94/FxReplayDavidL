| D5 | `money` is the control | Closest to FX Replay's current risk-free messaging on the homepage | Assumption about their baseline; not verified with the team | David |

| D8 | Target the Free plan (no card), not the 5-day paid trial | Lowest friction; matches "account creation" objective | Doesn't measure paid intent | David |
| D9 | No email delivery; result shown on screen | No free provider without a verified domain; instant gratification converts better anyway | Email promise removed from copy | David |
| D10 | GTM loaded deferred | Protects LCP / INP from the heaviest third-party script | May miss page views of very fast bounces; `account_created` is also sent server-side | David |
| D11 | Brand kit files flattened into `docs/brand/`; `tokens.json` and source PDFs not provided | Received without them; `tokens.css` regenerated from `brand-kit.html` | README structure differs from actual files | David |
| D12 | Only project-relevant MCP servers enabled: Mobbin, Playwright, Vercel — **Vercel superseded by D15** | Every connected server spends context on tool definitions the work never uses. Mobbin informs UI patterns, Playwright drives the a11y/perf audit, Vercel reports deploys, logs and preview URLs | Pinned in `.claude/settings.json` (`disableClaudeAiConnectors`, `enabledMcpjsonServers`) so it's versioned; a project-level `false` can't re-enable what a user- or policy-level `true` disabled | David |
| D13 | **Resolved by D16** — how `/` gets its variant: (A) `/` on-demand vs (B) prerendered variants + edge rewrite | Middleware runs at build time for prerendered pages, so it has no cookies or headers there. A prerendered `/` cannot be given a server-assigned variant. **A:** `export const prerender = false` on `/`; middleware assigns `fxr_variant` per request and passes it via `Astro.locals`. One page, one copy source, no flicker; `/` is served by a function instead of the CDN and ISR is unusable (it would cache a single arm). **B:** `middlewareMode: 'edge'`, three prerendered pages, middleware sets the cookie and rewrites `/`. HTML from the CDN; costs three pages to keep in sync and internal URLs that need canonical + `noindex` | Deferred to the variant-middleware step, not to the config step. `middlewareMode` stays unset until then | David |
| D14 | Vercel is operated only through its MCP (team `DavidLiraStuff`); the Vercel CLI and `gh` are off-limits in this repo, and deploys happen only via `git push` to `github-dlira94` | This machine holds three identities and none of the default ones are the project's: the Vercel CLI is on `david.lira@receptive.com` with the Receptive team active, `gh` is on `davidPettable`, and the project lives under `dlira94` / `DavidLiraStuff`. A `vercel deploy` here would have shipped into a client's account | One authenticated path instead of three, so a broken MCP auth blocks Vercel work rather than silently falling back to the wrong account. Manual deploys are given up on purpose: every deploy is traceable to a commit | David |
| D15 | Vercel MCP disabled in this project; Vercel is operated from the dashboard by David, deploys stay on `git push` | Re-authenticating the MCP against the Hobby scope that owns `fx_replay_david_lira` never granted project access: `list_teams` returned empty and `get_project` answered `403 Forbidden`. Two rounds of re-auth didn't move it, and the remaining paths (CLI, `gh`) are signed in to work accounts, which D14 rules out | No deploy state, logs or preview URLs in the agent loop: a human step between push and verification. Kept in `docs/ai-workflow.md` as proposed production tooling so the gap reads as a choice, not an oversight. The `vercel` plugin is turned off via `enabledPlugins`, which also drops its skills — none of them matched this Astro project | David |
| D16 | `/` is rendered on demand (`prerender = false`); the middleware assigns the variant per request and passes it via `Astro.locals`. Closes D13 option A | One page, one copy source, no flicker, and the exposure row is written from the same function that assigned the variant. Chosen partly on time budget: option B is more moving parts for a gain we can't yet size | `/` is served by a function, not the CDN, so TTFB is a function start and ISR is unusable (it would cache a single arm). Conditions: the exposure insert goes through `ctx.locals.waitUntil()` so the visitor never waits for the database; the middleware runs on `/` only, never `/api/*`, `/dashboard` or assets; `/` is `Cache-Control: private`. B (prerendered variants + edge rewrite + exposure by beacon) stays documented as the production optimisation. The cost of A is measured in `performance.md` | David |
| D17 | Exposures live in their own Postgres table, written by the middleware, idempotent on `anonymous_id` | The primary metric is conversions ÷ exposures and the SRM check runs on the denominator. Taking the numerator from Postgres and the denominator from GA4 would overstate conversion by whatever ad blockers eat, unevenly across arms, and would run the broken-assignment alarm on the least reliable number available | One insert per new visitor on the landing path, behind `waitUntil()`. `ON CONFLICT (anonymous_id) DO NOTHING`: the first variant assigned is the one that counts, so a returning visitor never switches arms. `experiment_exposure` stays in GA4 as the marketing mirror, and the gap between the two is a reconciliation metric rather than a discrepancy | David |
| D18 | Anything that isn't production traffic is written with `is_qa = true` — `VERCEL_ENV !== 'production'` (previews, local dev) or a `?variant=` override — on both `exposures` and `users` | Previews get a URL per branch and get clicked during review; without this, every QA pass contaminates the arm it touched. Flagging at write time rather than filtering later means the readout can't accidentally include it | Production is the only environment that produces analysable data, so the funnel can't be exercised end to end against real numbers before shipping. `is_bot` (user-agent heuristic) is recorded the same way: never blocked, always excluded | David |
| D19 | `GET /api/stats`: one aggregated, admin-only, PII-free endpoint serving exposures, quiz starts, conversions, drop-off per step and the SRM result | `/dashboard` and the `growth-analyst` agent need the same numbers. A single aggregate keeps the agent off the record-level endpoint entirely, so "never print names or emails" stops being a rule the agent has to follow and becomes something it cannot violate | One more endpoint to maintain, and its aggregates must stay in step with `analytics.md` §5. In exchange, `GET /api/users` stays the only PII surface and has exactly one consumer | David |
| D20 | Astro 7 + `@astrojs/vercel` 11: `waitUntil` is reached as `ctx.locals.waitUntil(promise)`, not through a separate `vercel-edge-middleware.js` | Verified in the installed adapter, whose deprecation warning names the new form. The older per-file handler is deprecated | It isn't in the adapter's published types, so `App.Locals` has to declare it in `src/env.d.ts` for strict TypeScript to accept it | Claude |
| D21 | Playwright does not manage the dev server; e2e runs against a server you started, or against a preview via `E2E_BASE_URL` | Astro 7's `astro dev` detaches and the foreground process exits even without `--background`, so Playwright's `webServer` reads a healthy start as a crashed one. Verified against the installed version | One manual step before running e2e locally. In exchange the same command runs against a Vercel preview unchanged, which is how this project verifies anyway (D15) | Claude |
| D22 | The project owns its own type, spacing, radius and container scales in `src/styles/scale.css`; `tokens.css` stays a verbatim copy of the brand kit | The brand kit defines colours and two font families and nothing else — no spacing or type scale — so components had no vocabulary for size or rhythm and were reaching for raw lengths. Type is fluid via `clamp()` so there are no breakpoint jumps | Two files instead of one, and a rule about which owns what: anything the brand defines lives in `tokens.css` and is never edited here; anything we invented lives in `scale.css`. If the brand ships a scale later, ours is the one that gives way | David |
| D23 | Elevation is surface lightness plus a 1px border, never shadow | On `--bg-primary` (#030303) a shadow is invisible, and `--card-bg-primary` is the *same* colour as the page background, so a card drawn with brand tokens alone cannot be seen. Four levels: page, section band, card, highlighted card | Sections carry their own background band, so nesting a level-2 card inside a level-1 band has to be deliberate. In exchange the hierarchy survives on OLED screens, where shadow-based depth disappears | David |
| D24 | Electric Blue marks where FX Replay enters the story, never decoration | StoryBrand: the brand is the *guide*, and the colour should appear exactly where the guide, the plan, success and the call to action are. **Blue:** primary CTA, chart playhead, focus ring, plan-preview card border, eyebrows (`--text-link`), the numbered steps and their connector, the "with FX Replay" panel. **Never blue:** the problem section, the villain, the "before" panel — those stay neutral. A landing where the accent appears everywhere teaches the eye that it means nothing | Costs some visual variety in the problem half of the page, which is the point: the contrast between neutral problem and blue solution is doing argumentative work | David |
| D25 | Inline errors use `--text-error` (`error-light`), never `--error` on a dark background | Measured: `--error` (#CD3636) on `--bg-primary` is **4.10:1**, which fails AA for small text — the same class of problem as brand blue in D7, and not previously recorded. `--error` remains correct as a *background* (`--bg-error`, `--banner-bg-error`) with light text on it | Recorded before the quiz ships its inline validation in block 3, where small red text is exactly what an implementer would reach for | David |
| D26 | The futures line in "where to practice" names the paid-plan requirement up front and offers an index as the meanwhile | This landing sells the **Free plan** — `research.md` §1: "'Try FX Replay Free' should lead to the Free plan (no card)". A futures trader who signs up, opens the app and finds their market gated converted on a promise the product does not keep, which costs more than the signup was worth. Saying it on the plan, next to a workable alternative, keeps the free offer honest without sending them away | The one place the page admits a limit, in a section built to earn a click. Worth it: the alternative is a bad first session. **Sourcing (resolved):** now cited in `research.md` §1 — LuxAlgo's platform overview (July 2025) states that *"the pricing table reserves seconds data and futures/CME access for Pro."* Read and verified, not taken second-hand. **Still a third party, not FX Replay's own pricing page, and over a year old**, so re-check against the live pricing page before production; if it no longer holds, drop the parenthetical and keep "ES and NQ at the New York open" | David |
| D27 | The testimonials section ships with written examples, each card labelled **"Sample testimonial"** in visible text; production feeds it from real Trustpilot reviews | The section earns its place in the StoryBrand order and can be designed, measured and reviewed now, without anyone having to pretend three strangers said these words. The label is on the card itself, not in a footnote — a disclaimer someone has to go looking for is a disclaimer designed not to be found | Weaker persuasion than real quotes, which is the honest trade: a fabricated testimonial presented as genuine is a lie about a real person's opinion, and no conversion is worth it. `research.md` §1 records ~600 Trustpilot reviews as the real source, so the swap is a data task, not a rewrite. Whoever does it must also delete the label | David |
| D28 | With JavaScript unavailable the header CTA stays hidden, and that is accepted rather than fixed | The stated principle is "no JS → everything visible", and this is its one exception. Showing it without JS means showing it over the hero too, where there is no room: the label is `[shared]` and cannot be shortened, so it wraps to two lines in a sticky bar — the exact defect the first audit caught. A no-JS visitor still gets four other primary CTAs, including the hero one immediately below | One element that a no-JS visitor never sees, in exchange for never shipping the wrapped-header regression again. Written down because an undocumented exception to a stated principle reads as a bug to the next person, who then "fixes" it | David |
| D29 | The quiz island runs on Preact via `@astrojs/preact` with `compat: true`, not React | Measured, not assumed: a trivial island (one button, one `useState`) ships **67.4 KB gzip** on React 19 + react-dom, against a 60 KB budget, and that is the floor before the real six-step quiz is added. The same probe on Preact ships **~10 KB gzip**. The 57 KB difference is not spent on a marketing page a visitor might never interact with — it is spent **at the exact moment someone decides to sign up**, on whatever connection they happen to have. A budget that only measured pre-interaction JS was measuring the cheap half of the page, so CLAUDE.md now carries a second one: under 25 KB gzip for the island on open | `compat: true` aliases react/react-dom to preact/compat, so the island is written as ordinary React and imports from `'react'`. Going back to React is a one-line config change rather than a rewrite, which matters because CLAUDE.md named React as the stack and a real production team may have reasons to keep it. The residual risk is third-party React libraries that compat does not cover; the quiz uses none | David |
| D30 | The shared Zod schemas are built on `zod/mini`, not the classic entry point | Classic Zod's builder API does not tree-shake: importing three schemas into the quiz island pulled in ~80 KB raw and put the island 67% over its 25 KB budget. Mini is the same library and the same validation, exposed as functions, so only the checks actually used get bundled | The functional API is wordier — `z.string().check(z.minLength(1))` instead of `z.string().min(1)` — and unfamiliar to anyone who has only used classic Zod. Worth it: the alternative was hand-written client validation that could silently drift from the server's, which trades a correctness guarantee for kilobytes. CLAUDE.md's "validate with the shared schemas on both client and server" survives intact | David |
| D31 | e2e splits by what it is testing: interface behaviour runs against **mocked** API responses, database behaviour has **dedicated** tests | A UI test should fail when the UI is wrong and for no other reason, so `page.route()` makes the network deterministic. **One** e2e still runs the full happy path against the real database, so island → endpoint → Postgres is genuinely exercised; the other 13 integration tests call the handlers directly. Suite time went from ~90s to ~15s, which matters more than it sounds: a slow suite gets run less often | Mocked responses can drift from what the API actually returns. Two things hold that line: the integration tests assert the real shapes, and the mocks return the envelope from `api.md` rather than an invented one. **Note on why the tests were flaky in the first place:** the original diagnosis — Neon latency — was wrong. Two real causes were found by measuring instead: Astro server-renders an island's markup and hydrates it after, so the inputs were visible and inert while the tests clicked them; and `useEffect` is deferred, so the step painted before the code that saved it ran. Mocking was the right structure regardless, but it was not the fix |
| D32 | `.quiz` carries a `min-height` equal to the tallest step | On a reload mid-quiz the server renders step 1 — it cannot read `sessionStorage` — and hydration swaps in the restored step about 250 ms later. Measured at 390 px: step 1 is 371.9 px, the tallest step is 527.3 px, and that 155 px growth measured **CLS 0.069** against a 0.05 budget. Lighthouse scores 0 on this page because the shift needs a returning visitor with a saved session, so nothing in CI would ever have caught it | A floor of 33 rem leaves empty space under the shortest step on a first visit. Accepted, and it buys something beyond the metric: the card stops resizing under the visitor's thumb at every answer, which the page below it was doing on every step. The restore can only land on steps 1–6 — `done` is not persisted — so the result screen being taller (698.8 px) does not reopen the gap | David |
| D33 | The quiz keeps the visitor's name and email in `sessionStorage` while the quiz is open | It is what makes "reload without losing your place" work, and the alternative — refetching answers from the server on every mount — would need the record to be readable by id, which is exactly what the edit-token design refuses. Cleared when the tab closes, never sent to analytics, never leaves the origin | "PII lives only in Postgres" (CLAUDE.md) reads stricter than what ships, so this is written down rather than left for a reader to file as a violation. The distinction that matters is upheld: no PII in analytics, and none in any durable store outside Postgres | David |
