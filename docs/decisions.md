# Decisions & assumptions

Lightweight log. Newest at the bottom. Format: **decision** · why · trade-off · who decided.

| # | Decision | Why | Trade-off | By |
|---|---|---|---|---|
| D1 | Astro (static) + React island for the quiz | Landing is content; zero JS by default protects Core Web Vitals. Only the quiz needs interactivity | Less common than Next.js; team may use Next | David |
| D2 | Vercel hosting (Hobby) | Static CDN + serverless API + edge middleware + preview URLs per branch, free | Hobby is non-commercial; production would need Pro | David |
| D3 | Neon Postgres + Drizzle | Persistence that survives serverless; DB-enforced unique email; real dashboard queries | Free-tier cold starts; external dependency | David |
| D4 | Copy-only test, 3 pains: `money` / `time` / `discipline` | Maximally distinct pains (money cost, time constraint, self-trust) so a result is informative | 3 arms need more traffic than 2 | David (from 6 researched options) |
| D5 | `money` is the control | Closest to FX Replay's current risk-free messaging on the homepage | Assumption about their baseline; not verified with the team | David |
| D6 | `btn-bg-primary-disabled` → `blue-900` | `blue-950` is referenced but undefined in the brand kit | Deviates from source tokens; flagged for design | David |
| D7 | Brand blue `#0260FD` not used for small text | Contrast 4.02:1 on `#030303` fails WCAG AA (4.5:1). Use `blue-500` (5.26:1) or `blue-400` (7:1) for small blue text | Slight visual deviation from pure brand blue | David |
| D8 | Target the Free plan (no card), not the 5-day paid trial | Lowest friction; matches "account creation" objective | Doesn't measure paid intent | David |
| D9 | No email delivery; result shown on screen | No free provider without a verified domain; instant gratification converts better anyway | Email promise removed from copy | David |
| D10 | GTM loaded deferred | Protects LCP / INP from the heaviest third-party script | May miss page views of very fast bounces; `account_created` is also sent server-side | David |
| D11 | Brand kit files flattened into `docs/brand/`; `tokens.json` and source PDFs not provided | Received without them; `tokens.css` regenerated from `brand-kit.html` | README structure differs from actual files | David |
| D12 | Only project-relevant MCP servers enabled: Mobbin, Playwright, Vercel — **Vercel superseded by D15** | Every connected server spends context on tool definitions the work never uses. Mobbin informs UI patterns, Playwright drives the a11y/perf audit, Vercel reports deploys, logs and preview URLs | Pinned in `.claude/settings.json` (`disableClaudeAiConnectors`, `enabledMcpjsonServers`) so it's versioned; a project-level `false` can't re-enable what a user- or policy-level `true` disabled | David |
| D13 | **Resolved by D16** — how `/` gets its variant: (A) `/` on-demand vs (B) prerendered variants + edge rewrite | Middleware runs at build time for prerendered pages, so it has no cookies or headers there. A prerendered `/` cannot be given a server-assigned variant. **A:** `export const prerender = false` on `/`; middleware assigns `fxr_variant` per request and passes it via `Astro.locals`. One page, one copy source, no flicker; `/` is served by a function instead of the CDN and ISR is unusable (it would cache a single arm). **B:** `middlewareMode: 'edge'`, three prerendered pages, middleware sets the cookie and rewrites `/`. HTML from the CDN; costs three pages to keep in sync and internal URLs that need canonical + `noindex` | Deferred to the variant-middleware step, not to the config step. `middlewareMode` stays unset until then | David |
| D14 | Vercel is operated only through its MCP (team `DavidLiraStuff`); the Vercel CLI and `gh` are off-limits in this repo, and deploys happen only via `git push` to `github-dlira94` | This machine holds three identities and none of the default ones are the project's: the Vercel CLI is on `david.lira@receptive.com` with the Receptive team active, `gh` is on `davidPettable`, and the project lives under `dlira94` / `DavidLiraStuff`. A `vercel deploy` here would have shipped into a client's account | One authenticated path instead of three, so a broken MCP auth blocks Vercel work rather than silently falling back to the wrong account. Manual deploys are given up on purpose: every deploy is traceable to a commit | David |
| D15 | Vercel MCP disabled in this project; Vercel is operated from the dashboard by David, deploys stay on `git push` | Re-authenticating the MCP against the Hobby scope that owns `fx_replay_david_lira` never granted project access: `list_teams` returned empty and `get_project` answered `403 Forbidden`. Two rounds of re-auth didn't move it, and the remaining paths (CLI, `gh`) are signed in to work accounts, which D14 rules out | No deploy state, logs or preview URLs in the agent loop: a human step between push and verification. Kept in `docs/ai-workflow.md` as proposed production tooling so the gap reads as a choice, not an oversight. The `vercel` plugin is turned off via `enabledPlugins`, which also drops its skills — none of them matched this Astro project | David |
| D16 | `/` is rendered on demand (`prerender = false`); the middleware assigns the variant per request and passes it via `Astro.locals`. Closes D13 option A | One page, one copy source, no flicker, and the exposure row is written from the same function that assigned the variant. Chosen partly on time budget: option B is more moving parts for a gain we can't yet size | `/` is served by a function, not the CDN, so TTFB is a function start and ISR is unusable (it would cache a single arm). Conditions: the exposure insert goes through `ctx.locals.waitUntil()` so the visitor never waits for the database; the middleware runs on `/` only, never `/api/*`, `/dashboard` or assets; `/` is `Cache-Control: private`. B (prerendered variants + edge rewrite + exposure by beacon) stays documented as the production optimisation. The cost of A is measured in `performance.md` | David |
| D17 | Exposures live in their own Postgres table, written by the middleware, idempotent on `anonymous_id` | The primary metric is conversions ÷ exposures and the SRM check runs on the denominator. Taking the numerator from Postgres and the denominator from GA4 would overstate conversion by whatever ad blockers eat, unevenly across arms, and would run the broken-assignment alarm on the least reliable number available | One insert per new visitor on the landing path, behind `waitUntil()`. `ON CONFLICT (anonymous_id) DO NOTHING`: the first variant assigned is the one that counts, so a returning visitor never switches arms. `experiment_exposure` stays in GA4 as the marketing mirror, and the gap between the two is a reconciliation metric rather than a discrepancy | David |
| D18 | Anything that isn't production traffic is written with `is_qa = true` — `VERCEL_ENV !== 'production'` (previews, local dev) or a `?variant=` override — on both `exposures` and `users` | Previews get a URL per branch and get clicked during review; without this, every QA pass contaminates the arm it touched. Flagging at write time rather than filtering later means the readout can't accidentally include it | Production is the only environment that produces analysable data, so the funnel can't be exercised end to end against real numbers before shipping. `is_bot` (user-agent heuristic) is recorded the same way: never blocked, always excluded | David |
| D19 | `GET /api/stats`: one aggregated, admin-only, PII-free endpoint serving exposures, quiz starts, conversions, drop-off per step and the SRM result | `/dashboard` and the `growth-analyst` agent need the same numbers. A single aggregate keeps the agent off the record-level endpoint entirely, so "never print names or emails" stops being a rule the agent has to follow and becomes something it cannot violate | One more endpoint to maintain, and its aggregates must stay in step with `analytics.md` §5. In exchange, `GET /api/users` stays the only PII surface and has exactly one consumer | David |
| D20 | Astro 7 + `@astrojs/vercel` 11: `waitUntil` is reached as `ctx.locals.waitUntil(promise)`, not through a separate `vercel-edge-middleware.js` | Verified in the installed adapter, whose deprecation warning names the new form. The older per-file handler is deprecated | It isn't in the adapter's published types, so `App.Locals` has to declare it in `src/env.d.ts` for strict TypeScript to accept it | Claude |
